# 开饭 · HTML 手机 App 原型

原生 HTML/CSS/JavaScript，无前端构建步骤。手机浏览器显示完整 App 页面，电脑浏览器显示手机预览与流程说明。

## 启动

在仓库根目录运行：

```bash
uv sync --extra test
.venv/bin/python -m service
```

浏览器打开 <http://127.0.0.1:8000>。端口冲突时可使用 `--port 8001`。不要双击 HTML 文件：计划生成依赖同源的 Python API。按 Ctrl+C 停止服务。

## 推荐体验路线

1. 菜谱页默认选择「可乐鸡翅、番茄炒蛋、清炒生菜、米饭」。点击名称可编辑，右侧勾选控制本餐菜单，爱心切换收藏。
2. 点击文字、图片或链接导入，载入明确标注的固定「番茄炒蛋」示例。修改菜名、食材、步骤、详细操作备注、时长、关注方式和前置依赖后保存。手动创建可以增加独立任务。
3. 在「我的 → 厨房设备」修改资源数量。把炒锅设为 0，生成计划时可以看到具体的资源不足提示；恢复为 1 后继续。
4. 在「做饭」设置开饭日期时间并生成计划。时间线和资源占用条来自真实 CP-SAT 输出；超时未证明最优的可行解与开饭延误会分别标记。
5. 点击「开始烹饪演示」，从建议开始时刻启动演示时钟。开始第一步后，手动操作显示在主卡片，电饭煲等设备在独立区域持续计时；操作备注会始终显示在对应任务中。点击「确认并进入下一步」，无需再次点击开始；引擎会自动衔接到时且满足依赖与资源约束的步骤。
6. 设备任务的预计时间到后，完成按钮显示自动确认倒计时，默认 60 秒，可在生成计划前或执行页设为 5–600 秒。倒计时到期自动确认并衔接；可点击「本次不自动确认」取消，或「再给 5 分钟」延长任务。手动与明火步骤仍需确认。每次开始、完成、延长及手动重排都调用真实引擎。`+1 分钟` / `演示快进到这一步` 可加速体验，直到出现完成页面。
7. 刷新页面，菜谱、厨房与已提交的执行事实会从当前浏览器恢复。「我的 → 重置演示数据」会先询问，再恢复默认数据。

## 真实能力与演示边界

| 能力 | 本阶段实现 |
| --- | --- |
| 生成计划、动态重排 | 真正调用现有 OR-Tools 调度库 |
| 任务开始/完成 | 浏览器维护会话快照，真实调度校验成功后提交本地状态；确认后自动启动符合条件的下一步 |
| 菜谱、收藏、厨房 | 浏览器 localStorage，不是服务端数据库 |
| 图片/链接/文本导入 | 固定示例流程；不上传图片、不抓取 URL、不调用 AI |
| 手动编辑 | 支持步骤名称、操作备注、时长、关注方式、依赖及单步骤厨具；循环依赖会被拦截 |
| 跨步骤厨具占用 | 保留示例 holds，显示占用起止；可视化编辑器待后续设计 |
| 暂停 | 仅冻结演示时钟；不是正式厨房暂停语义 |
| 计时结束 | 自动设备任务进入确认倒计时后自动完成；手动与明火任务必须手动确认 |
| 离线与通知 | 已加载页面可看计时；状态变更/重排需要服务，网页关闭后无系统通知 |
| 登录、多设备、持久化 API | 尚未实现 |

执行中的会话使用冻结的菜谱与厨房快照；修改下一餐的菜谱或厨房不会重写当前会话。重排期间演示时间不计入用户耗时。确认等待期间保留人员和设备占用。过期但未确认完成的任务在重新求解时仍至少预留 60 秒占用；手动步骤不会因此被视为完成。仅 `passive` 且关联电饭煲、烤箱、微波炉或空气炸锅的任务允许自动确认；直接或跨步骤占用灶眼的任务不会自动确认。

自动衔接遵循最新调度结果：到达计划时间、依赖已完成且资源允许，才会启动。若下一步尚未到时，页面显示等待并在到时后衔接，不会为赶进度跳过依赖。设备与手动任务如果同时符合条件，可以同时开始。

倒计时使用会话相对时间，刷新后不重置；演示暂停时也暂停。浏览器恢复运行时以当前时刻处理到期事件，不补造离线期间的执行历史。网络失败会限制自动重试频率；若完成确认已同步但下一步启动失败，会保留已同步的进度，不会把未通过调度校验的下一步标成已开始。本次取消自动确认可离线保存。

当前是单浏览器标签页演示，不支持多标签并发修改。手机浏览器原型不能代替 Flutter 实机后台通知与离线验收。

## 文件

- `index.html`：App 容器、桌面说明、底部导航、原型说明弹窗。
- `styles.css`：响应式视觉样式，无外部字体或图片依赖。
- `data.js`：四道演示菜谱、明确的 DAG 和持续资源占用、默认厨房。
- `app.js`：页面、表单校验、状态持久化、调度 API 调用和演示计时器。
- `execution.js`：依赖就绪判断、完成倒计时、设备判定和会话到调度请求的转换。
- `tests/execution.test.cjs`：无依赖的执行状态测试，运行 `node frontend/tests/execution.test.cjs`。
- `assets/mark.svg`：本地品牌图标；菜品插画由 SVG 生成。

## 服务接口

- `GET /api/health`：检查引擎服务。
- `POST /api/v1/plans/generate`：提交调度 `Request`，返回 `Plan`。
- `POST /api/v1/plans/recalculate`：同一请求结构，包含 `now_seconds` 和 `execution`。
- `GET /project-plan`：项目规划文本。
- `/docs`：本地 OpenAPI 交互文档。

接口是无持久化的原型适配层。默认只绑定本机地址，尚不适合直接公开部署。
