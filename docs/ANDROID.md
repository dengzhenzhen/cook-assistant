# Android 安装与使用

当前版本 0.1.3，支持覆盖安装保留账号和本地数据。若后端仍是 0.1.0 之前的版本，需重启以启用可选开饭时间接口。

本轮安装包：[kaifan-0.1.3-debug.apk](../dist/kaifan-0.1.3-debug.apk)（约 184 MB），[SHA-256](../dist/kaifan-0.1.3-debug.apk.sha256)。签名与三种架构已检查：armeabi-v7a、arm64-v8a、x86_64。最低支持 Android 7.0（API 24）。

## 启动后端

在仓库根目录运行：

```bash
uv sync --extra test
.venv/bin/alembic -c backend/service/migrations/alembic.ini upgrade head
.venv/bin/python -m service --host 0.0.0.0 --port 8002
```

若旧版本后端仍运行，先在其终端按 Ctrl+C，再重新启动以上命令。保留终端运行。手机和电脑连接同一局域网，在登录页填写 `http://电脑的局域网IP:8002`，然后注册邮箱和密码（至少 8 位）。这是本项目自己的账号，不需要 DeepSeek 账号。WSL 用户须确保 Windows 防火墙和 WSL 网络转发允许手机访问 8002；先用手机浏览器打开 `http://电脑IP:8002/api/health` 验证。

也可以通过 USB 调试连接电脑，运行 Android SDK 的 `adb reverse tcp:8002 tcp:8002`，使用 APK 默认服务器 `http://127.0.0.1:8002`。默认地址不是已部署的云服务。

## 安装与编译

本轮产物是开发测试 APK，允许局域网 HTTP，使用 Android 调试签名。无需发布商店；在手机文件管理器中点开 APK，允许该来源安装应用。

重新编译：

```bash
cd frontend/mobile
../../scripts/flutter.sh pub get
../../scripts/flutter.sh build apk --debug \
  --dart-define=API_BASE_URL=http://127.0.0.1:8002
```

输出为 `frontend/mobile/build/app/outputs/flutter-apk/app-debug.apk`。正式发布需另行配置自有签名和 HTTPS API，并执行 `build apk --release`；当前调试签名不作为商店发布签名。

## 完整流程

1. 注册/登录，导入或手动创建菜谱，检查备注、依赖、资源并保存。
2. 选择菜谱，检查厨房设备数量。开饭时间可选，默认按尽快完成安排；设备不足会弹窗并显示持续错误提示。生成计划后点击「开始烹饪」。
3. 当前手动/明火任务与自动设备任务分别显示。后台等待/加热步骤尚未到期时，点击完成需再次确认；取消后继续计时。全部完成后点击「完成并返回菜谱」，会保留本地完成进度及未同步状态。
4. 允许通知和精确闹钟权限，锁屏检查到期提醒。拒绝权限时界面提示，设置页可重新开启。
5. 断网后仍可执行已下载计划和保存菜谱/厨房编辑；回到应用且联网时自动重试同步。冲突由用户选择，不静默覆盖。

暂停只停止新步骤，正在运行的锅灶、设备与计时继续。自动设备到期后默认等 60 秒确认，可选 5–600 秒。后台由系统提醒；回到前台再补算进度，不在后台启动人工操作。

## 验收边界

邮箱验证、密码找回、云部署、WebSocket 推送不包含在本轮。执行同步在执行页开启时每 10 秒尝试，编辑队列在客户端打开时每 20 秒尝试，后台不常驻联网。新账号不会自动接管旧开发账号菜谱。

编译成功只能证明 APK 已生成；通知权限拒绝、锁屏、系统省电限制、重启恢复及真实三菜烹饪仍需 Android 手机验收。iOS 通知代码已配置，iOS 编译签名需 macOS/Xcode。

## 0.1.2：WSA 输入与等待期间提醒

WSA 自动启用清空输入框后的缓存重置，手机 Android 不启用此兼容分支。请用「输入 ABCD → 全部删除 → 输入 Z」复测，应只留下 Z。隔离 WSA 应用的 Windows 键盘逐字删除、全选删除重输测试通过；原始回填现象未能在自动化中稳定复现，仍需用户原操作验证。

指定开饭时间时，执行保留原定时刻。提前完成设备启动步骤后，直接进入同道菜的被动炖煮阶段；其他菜不会因此提前炒制。等待页展示后续操作时间，预先登记「该回厨房了」系统提醒。通知仅提醒，休息状态下不会替用户启动设备或记录人工步骤已开始。用户回来后点击「开始这一步」；需要提前操作时可显式确认提前开始，随后重新规划。

无手动工作且设备可自动运行时可以暂时休息；明火仍需看管。暂停安排新步骤时保留运行计时到期提醒，暂停后续开工提醒。旧目标时间会话会恢复原定开饭时刻，但不改动实际执行记录。

已在独立 WSA 测试包验证：应用最小化后，30 秒后的开工闹钟产生系统通知。诊断包和测试通知已清理，正式应用数据未改动。Android 手机、设备重启和不同厂商省电模式仍待实测。

## 0.1.3：WSA 菜谱输入

WSA 的导入文字、菜名、份数、食材、操作名称、备注和时长改用系统编辑框。点击字段或右侧编辑图标，直接使用键盘输入，点击「完成」回填；点击「取消」保留原文。「清空」可明确删除全部内容。普通 Android 手机与 Web 继续使用内联输入框。

该版本已在当前 WSA 覆盖安装，保留原账号和本地菜谱。验证使用未提交的导入文字及未保存的新建菜谱，不调用 AI、不创建测试菜谱记录。

## 0.1.3：WSA 菜谱字段输入

点击导入文字或菜谱字段（也可点右侧编辑图标），会打开系统编辑框。用键盘输入，点击「完成」回填；点击「取消」保留原文；需要全部删除时可用「清空」。此方式仅在 WSA 启用，Android 手机和 Web 保留内联编辑。

已在当前 WSA 覆盖安装 0.1.3 并验证正式应用：导入文本输入及回填、取消保留，菜名、份数、食材、操作名称、备注和时长的输入。中文使用 Windows 拼音输入法验证。测试只使用未提交的导入内容和未保存的新建菜谱，未调用 AI 或保存测试菜谱。Android 手机仍未实测。
